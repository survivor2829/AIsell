# 微信拓客异机测试：出问题后怎么把日志发回来

适用于在其他电脑上测试精准触达、朋友圈、自动回复的同事。按下面四步操作，开发这边才能定位原因。

## 出问题时

1. **先别关软件，也别关微信。** 程序停下或提示异常时，保持当前画面。
2. **记下三件事**（手机拍一下屏幕也可以）：
   - 大概几点几分出的问题；
   - 当时在做什么：精准触达、朋友圈还是自动回复，第几位联系人；
   - 软件上显示的提示原文。
3. **在软件里提交反馈**：左侧导航点「吐槽中心」→ 写一句发生了什么 → 提交。提交后在「我的反馈」里能看到这条记录。
4. **导出诊断包**：还在「吐槽中心」页面，展开下方「日志诊断」→ 点「导出诊断包」→ 保存到桌面。文件名形如 `AI获客 V1.0版本-诊断日志-<时间>.zip`。

## 发回来

- 把诊断包 zip 和第 2 步记下的三件事一起发给开发。
- 诊断包里有微信界面截图，可能包含客户聊天和联系人信息。**只发给开发本人**，不要发到群里。

## 恢复继续

- 界面上如果写着"消息未发送，可安全继续"或"可以重新加入"：点「重新加入」→「启动程序」即可继续。
- 如果写着"发送结果无法确认"：**先打开微信，看那位联系人是否已经收到消息**，再按实际情况选择"已发送 / 未发送 / 跳过"。不要猜，也不要重复手动发送。

## 开发侧（收到诊断包后）

1. 用 `desktop/scripts/analyze-diagnostics.cjs`（T9 实现后可用）生成时间线，看这几项：
   - 环境：微信版本、DPI、构建号；
   - 失败的原因码和 rule_id；
   - 发送状态；
   - 全局停机后多久恢复。
2. 按 `docs/failure-evidence.md` 的阅读顺序核对 `trace_id`。
3. 区分"已确认的原因"和"待验证的假设"，写任务卡交给 Codex；修复后走 `release:internal`，再请同事复验。原因没定位到时，先补诊断字段，下一轮再测。
