## 一、总判断

内容创作 v2 主流程（素材与需求 → 确认文案 → 制作与成片）的方向是对的，与"只要确定文案方向就行"的目标已接近。当前三个问题定性如下：

1. **"15 分 3 秒就停"不是故障，是一个用户完全看不见的 15 分钟墙钟预算到点。** 已在本机数据实锤（见下）。预算本身（防失控计费）是合理的 fail-safe，**错在两点：预算把本地处理时间也算进去、停了以后用户看不懂也找不到原因**。
2. **配置摩擦确实存在，且集中在三处**：火山方舟 Key（素材理解/文案）、火山 TTS Key（配音）、"已批准声音"（必须生成→试听→批准）。它们分散在 3 个不同页面，新机冷启动必然卡在"确认制作"按钮上。
3. **工作台的问题不是缺功能，而是三代流程并存**：v2 新流程、v1 旧批次分支、旧工作台（课程/混剪/三风格对照）全部挂在同一个入口下，新用户极易误入旧流程。

## 二、"生成累计 15 分 3 秒就停"——根因实锤

### 2.1 运行数据证据（本机 test 数据目录）

`C:\Users\Scott\AppData\Roaming\xiaoxi-active-touch-test\content-engine\content-engine.sqlite3`：

```
task_8f026245...  status=failed
error_code=narrated_planning_budget_exhausted
error_message=本次已达到 12 次实际模型请求或时间预算，已有结果已保存。
created_at=2026-09-15T12:37:39.912Z   updated_at=2026-09-15T12:52:43.792Z
```

耗时 903.88 秒 = **15 分 3.9 秒**，与你描述的"累计 15 分 3 秒"精确吻合。

批次状态：`needs_attention`，原因文本为上面那句；`_planning_budget` 显示 **max_elapsed_seconds=900，实际云端调用只用了 1/12 次**。

`provider-usage.jsonl` 时间线（UTC，+8 即本地）：
- 20:41:37 ASR 识别（114 秒音频）
- 20:41:40 LLM 画面理解（11 秒，成功）
- **20:41:52 → 20:52:35 之间 10 分 48 秒无任何云端请求**——全部耗在本地：大疆素材 `DJI_20260829104738_0083_D_A001.MP4`（330 秒长视频）的抽音频/代理/抽帧等 ffmpeg 处理
- 20:52:43 最后一次 ASR 成功返回，随即到达 900 秒上限，任务停止

### 2.2 机制（代码证据）

- `narrated_batch.py:4270`（`_run_script_workflow`，action="scripts"）：
  `'max_cloud_calls': asset_count * 2 + 4, 'max_elapsed_seconds': 900` —— **900 秒是固定值，不随素材数量/时长缩放**。
- `narrated_batch.py:1029-1035`（`_admit_request`）：
  `remaining = budget['max_elapsed_seconds'] - (time.time() - budget['started_at_epoch'])`，`remaining < 2` 即抛 `narrated_planning_budget_exhausted`，批次置 `needs_attention`。
  **计时起点是任务启动的墙钟**，中间的本地 ffmpeg、转写、抽帧、等待全部计入——但云端调用额度只消耗了 1 次。
- 同类预算共三处（同一设计，同一问题）：
  - `narrated_batch.py:4270` 生成文案阶段：900 秒固定
  - `narrated_batch.py:3482`（`_plan`）：v2 为 300 秒×容量，v1 为 1200 秒×容量
  - `narrated_production.py:443-447` 制作阶段：900 秒×作品数

### 2.3 为什么你感觉"莫名其妙就停了"

- 界面上批次状态只显示"**需要处理**"四个字；具体原因放在默认折叠的"项目详情"里（`BatchCreativePage.tsx:433`，`<details className="batch-advanced">` 默认收起）。
- 错误消息（`narrated_batch.py:1031`）"本次已达到 12 次实际模型请求或时间预算"：没说是 15 分钟上限，没说**再点一次"生成文案"就能续跑**（每次 scripts 会重建预算 `:4268`，已完成的分析有缓存、不会重复付费调用——这句话 UI 在别处有，但没跟这个错误放在一起）。

### 2.4 修复方向（供你核对后交 Codex）

1. **预算口径**（P0）：要么把 900 秒改为"仅云端请求活跃时间"，要么按素材量缩放（如 900 秒 + 每个素材 N 秒），要么按已有 checkpoint 分段（`_visual_fact_checkpoints` 机制已存在，每完成一个素材重置计时）。**不建议取消预算**——它防止云端调用失控，是有意设计。
2. **消息明确化**（P0）：exhausted 文案改为说人话，例："素材理解累计耗时达到本次 15 分钟上限（云端调用仅用 1/12 次，已保存的分析不会浪费）。点击"生成文案"将从已完成的分析继续，不会重复付费调用。"
3. **原因直显 + 一键继续**（P0）：`needs_attention` 时把 reasons 直接显示在进度面板（不折叠），并放一个"继续生成"按钮（等价于重发 scripts action）。

## 三、配置流程——摩擦点清单与简化方案

### 3.1 现状摩擦点（代码证据）

| # | 摩擦 | 位置 |
|---|------|------|
| 1 | 火山方舟 Key（必需，素材理解+文案）输入框在**旧工作台侧栏** | `CreativeWorkspacePage.tsx:1810-1813` |
| 2 | 火山 TTS Key（必需，配音）输入在"声音管理"，入口藏在 制作记录与工具 → 其他创作方式 → 商品单片与声音资源 | `BatchSoundSettings.tsx:66`；`BatchCreativePage.tsx:312` |
| 3 | "确认文案，开始制作"强制要求已批准声音，否则按钮禁用 | `BatchCreativePage.tsx:418` `disabled={... \|\| !settings.voice_persona_id}`；`:420` 提示 |
| 4 | 声音必须走 生成 → 试听 → 批准 三步才能进入可选用池 | `AutoMixResourcePanel.tsx:672-792`（"试听后，固定喜欢的声音"） |
| 5 | AI 封面固定依赖 APIMart（仅旧工作台） | `CreativeWorkspacePage.tsx:1703`（下拉固定"AI 封面（固定）"）、`:1013` |
| 6 | 未配置时的报错只说"请先配置"，不带跳转 | `narrated_batch.py:1044` "请先配置当前模型平台…" 等 |

结论：新机冷启动最少需要 **2 个 Key + 1 轮声音生成/试听/批准**，且三件事分散在 3 个页面。这就是你说的"又要试用、试听"。

### 3.2 简化方案（一切从简，按性价比排序）

1. **内置默认音色（P1，收益最大）**：预置 1 个官方默认音色（固定 voice_type 或预生成样本，批准状态直接为 approved）。确认制作时未选声音就用它，"试听/换声音"降级为可选项。此后新用户主流程只剩：**选素材 → 填一句方向 → 生成文案 → 选一条 → 点制作**。声音人格管理保留为高级入口。
2. **一个"开始前准备"引导页（P1）**：进入创作工作台时检测三项状态（方舟 Key / TTS Key / 默认音色可用），缺什么补什么，每项带直达输入框；所有"请先配置…"类报错附"去配置"按钮（错误码已通过 IPC 返回，renderer 有条件路由）。
3. **合并火山凭据入口（P2）**：方舟 Key 与 TTS Key 同属火山引擎，合并为一个"火山引擎凭据"卡片一次填写；APIMart 只服务旧工作台，从新流程视野中完全隐藏。
4. **配乐保持默认不选（已支持）**，不要在首屏强推试听曲库。
5. **恢复说明减负（P2）**：结果不明后的人工恢复要求写 1000 字内核对依据（`narrated_batch.py:763`）。这道闸是防重复付费的**正确设计，不要删**；但 UI 可以提供一句话模板按钮（如"已核对火山控制台，无对应调用记录"），降低填写负担。

### 3.3 需要你拍板的产品决策（建议一次性定死）

1. 默认音色方案是否接受？涉及默认音色选谁（男/女、风格）与 TTS 计费归属。
2. "别人电脑零配置"的边界：是"装好→向导里贴 2 个 Key（约 5 分钟）"，还是你愿意出官方 Key 池/代理（真零配置，但计费与合规口径要单独定）？**这决定方案天花板**，建议先按前者落地，后者作为独立课题。

| 动作 | 对象 | 理由 |
|------|------|------|
| 隐藏（数据保留） | BatchCreativePage 的 v1 旧流程分支（三分组拖拽、样片流程） | v2 已覆盖同能力；旧批次已有归档机制可查看 |
