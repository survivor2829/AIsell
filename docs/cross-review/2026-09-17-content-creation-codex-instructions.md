### F-3（P1）默认音色内置（按已拍板决策实施，不再等方案确认）

- 落点：声音资源层（`auto_mix_resources.py` / voice_personas 表）预置一个 approved 状态的默认音色；`BatchCreativePage.tsx:418` 的 `!settings.voice_persona_id` 硬校验放宽为"未选时自动用默认音色"，UI 提示"未选声音，将使用默认音色，可在高级设置更换"。
- 默认音色选型：从火山已有音色中选一个通用中性男声或女声（建议女声、语速中等，适合产品讲解），写死为内置默认，不再走"生成→试听→批准"强制三步；试听保留为可选预览，不是闸门。
- 前置依赖：默认音色要真正出声，需要服务端 TTS 能力可用（见 F-5 第 1 条）。客户端逻辑先行，服务端就绪前联调用本地兜底 Key 验证链路，验收环境说明写清即可。
- 验收：无任何已批准人格时，确认制作可走通且成片配音成功；人格选择逻辑（`preferredVoice`）不受回归影响。

### F-4（P0·已升级）客户零配置：移除内容创作流程中的所有 Key 配置触点

决策依据：用户拍板"API 全部云端默认配好，客户只管用"。现状是客户端已具备网关自动注入能力（`main.cjs:553-582`：网关能力可用时自动注入 deepseek / apimart / volcengine_ark / volcengine_tts / volcengine_asr 的令牌与 URL，本机 Key 仅在能力缺失时兜底），**主要工作是收掉客户可见的配置入口和报错方式**：

1. **隐藏配置入口**（renderer）：内容创作主流程内不再出现任何"填 Key / 配置 API"的引导：
   - 火山方舟 Key（旧工作台侧栏）——从内容创作流程隐藏；
   - 火山 TTS Key（"其他创作方式→商品单片→声音管理"三层深处）——同上。
   - 侧栏"API密钥"页保留但标注为高级功能入口，不在创作流程内主动跳转引导（是否整体下线，等交付版网关正式启用后再定，本轮不动）。
2. **报错说人话**：网关不可用 / 能力缺失 / 令牌过期时，面向客户的文案一律是"AI 服务暂时不可用，请稍后重试；持续失败请联系我们"，不出现"Key 未配置 / 请填写密钥"字样。技术性错误码只进日志，不进客户可见 notice。`cloud_not_configured` 等 code 仍透传给日志与诊断，但 renderer notice 文案改为人话。
3. **配置预检静默化**：内容创作启动时不再做"必须先配置才能开始"的强拦截；能力缺失时允许进入流程，在具体调用失败点给出上述统一文案。
4. **v1 旧流程分支**从默认视图隐藏（数据与归档查看保留）。
- 验收：**全新安装环境（零 Key、零本地配置）**在网关可用环境下从创作工作台走通"选素材→写方向→生成文案→选文案→制作"全流程，全程不出现任何配置引导；断网/网关故障时每一步的报错都是统一人话文案且可重试。

### F-5（P0·新增）服务端配套：网关 Key 部署 + 交付版启用 + 额度控制

这一条主要是服务端/运维工作，不是客户端代码，但属于本决策的硬前提，Codex 负责提出清单与验收脚本：

1. **网关 Provider Key 部署**：在服务器网关环境写入 `XIAOXI_GATEWAY_VOLCENGINE_TTS_API_KEY`（当前服务端未配专用 TTS Key，见 `API_CONFIG.md` §测试版统一网关）及 Ark / DeepSeek / APIMart 各 Key，部署后实测 `/capabilities` 五项能力全部为 true。
2. **交付版启用网关**：`API_CONFIG.md` 明确"交付版仍关闭测试网关配置"。需走正式域名 + 正式证书 + 正式授权码验证后，在交付版构建中打开网关开关；这是客户零配置成立的必要条件。
3. **云端额度控制（最小版）**：网关侧当前没有服务端额度结算（`API_CONFIG.md` §当前服务边界）。最小实现：按安装授权主体在 `service.py` 记录每日调用次数/字符量（文案 token 数、TTS 字符数），超限时返回明确错误码（如 `gateway_quota_exceeded`），客户端把它映射为"今日 AI 使用额度已用完，明天自动恢复"级别的人话提示。不做账户系统、不做计费结算——那是后续版本的事。
4. **验收**：交付版安装包 + 零本地配置的新机器，连续跑内容创作主流程，观察网关侧用量记录与额度拦截行为；额度超限路径需实测一次。
- 硬约束：供应商 Key 只存服务器受保护环境文件，不进客户端包、日志或诊断；网关不接受客户端传入的上游 URL（现状规则保持）。
