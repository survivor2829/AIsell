## 反馈本机 HTTP 闭环

使用临时数据库和两个本机回环 HTTP 服务，分别模拟公网接收面与仅供管理的后台。现有 `test_feedback_receipt_access_retention_and_admin_status` 已通过，检查了：

- 相同 ID、固定内容和凭据重复提交返回原记录的当前回执；内容冲突返回 409。
- 查询必须持有对应回执凭据，缺失或错误凭据返回 403；公开端不提供反馈列表。
- 后台更新要求正确的本机 Host 与同源 Origin；合法更新可从客户端状态接口读回。
- 连续不同状态更新时间严格递增；重复相同状态不伪造新的更新时间。
- 服务端只保留凭据摘要，诊断采用白名单；诊断过期后正文、处理状态和幂等记录继续保留。

客户端定向自检同时确认：先写盘再发送，队列写入失败保留草稿；回执写盘失败可在原 ID、原快照和原凭据下恢复；旧或冲突回执不能倒退状态；IPC 错误不暴露磁盘路径；取消附带诊断时不读取和发送诊断条目。

**实际 TEST 云端新增反馈服务尚未部署。** 本机 HTTP 通过不等于真实云端已经接收反馈。部署需包含同版本 `feedback.py`、`service.py` 和后台文件；部署后仍需完成实际客户端提交、后台修改、客户端刷新闭环。合同见 [维护服务说明](../../server/maintenance/README.md)。本次没有执行这些部署步骤，也没有将任何凭据或原始云数据库内容写入本报告。
