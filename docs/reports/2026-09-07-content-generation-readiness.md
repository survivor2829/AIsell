# 内容创作：生成标准、调用清单与固定验收方案

> 2026-09-07 历史记录。三个方案、第一稿框架及旧调用预算已由 [2026-09-12 流程精简](2026-09-12-content-simplification.md) 替代；当前产品约定见 [PRODUCT.md](../../PRODUCT.md)。

本轮仅进行源码调整和本地验证，不发起付费 AI 调用。用户已报告服务欠费；之前的 HTTP 403 与结果未知记录仍保留，充值不等于这些历史请求已自动解决。

## 统一生成与审核标准

生成和文案复核共用 `narrated_brief.py` 的 `RULES`。输入为素材池、必填受众、选填“你想表达什么”、选填结尾引导；表达栏容纳身份、经历、事件背景、优势、痛点和故事。这个框架同时记录在 `PRODUCT.md`，作为后续开发约定。

| 项目 | 生成要求与验收依据 |
| --- | --- |
| 同一受众，三个切入点 | 三个方案解决不同子问题，不仅更换标题或措辞；每条无需覆盖所有优势和痛点。卡片先呈现概要和开头，单选展开正文。 |
| 第一个方案 | 提出具体问题，给出有依据、观众能执行的办法，最后引导行动。空泛介绍能力不算解决办法。 |
| 用户背景 | 可引用用户明确提供的身份和背景；审核保留对应的原文引用。未明确哪个人对应哪份素材时，不猜测姓名，不把不同人物当作同一学员。 |
| 效果与事实 | 用户背景不自动证明性能、收益、培训效果或人物跨镜头连续性。涉及画面或原声事实仍核对素材；不足则删改或补充资料，不通过虚构补时长。 |
| 长度和成片 | 最终视频至少30秒，口播与字幕覆盖完整；不能用静音、重复镜头或无关内容填充。预计时长不是验收证据。 |
| 结尾 | 用户引导进入口播和字幕，突出文字对齐实际字幕尾句，避开字幕安全区。实际发音、显示时间和完整播放均需验收。 |
| 修改与复用 | 需求或正文变化使相关审核失效；内容未变且审核键匹配时复用结果。明确清空表达栏后不能恢复旧优势／痛点。 |

事实审核有独立的证据规则。本轮已去掉该阶段重复附加的整套写作指令，仅发送必要事实规则和一份用户背景；不删事实检查，也未测得实际费用降幅。

## 当前调用清单

下表是逻辑阶段，不承诺一阶段恰好一次计费请求；模型传输层的结构化重试也可能产生请求。

| 阶段 | 用途、输入与产出 | 触发、复用与失败处理 |
| --- | --- | --- |
| 素材分析／语音识别 | 输入素材及其音频，产出分段原声、语义和可用内容 | 缺少有效分析时调用；素材分析保存在 `media_segments`，按版本和服务配置复用。失败保留状态，不视作素材没有内容。 |
| 画面事实提取 | 输入所需帧，产出可见事实与关联证据 | `narrated_visual_facts` 已有持久化缓存，抽帧文件也可复用；不能因缓存缺失跳过必要检查。 |
| 三个选题生成／修正 | 输入素材依据、受众、表达、结尾与统一规则，产出标题、概要、正文、结构和建议 | 保留已通过方案，只修正缺失或不合格部分；反馈进入续做。当前单轮规划预算为最多8次逻辑云调用、900秒、最多3轮尝试，不是全链路费用封顶。 |
| 文案语义复核 | 判断受众、切入点、具体办法、结尾及背景是否符合需求 | `_brief_review_hash` 按规则、需求、结构、标题、规范化正文复用；修改相关内容后重新检查。 |
| 正文与镜头映射 | 输入确认正文和素材依据，输出段落与片段编排 | 首条保留确认正文；映射最多3轮尝试。容量不足先做本地同活动可用片段分配，不重复画面。 |
| 逐段事实审核 | 输入段落、上下文及绑定依据，产出声明与证据结论 | 当前逐段调用（含标题），不是整个视频只调一次。`_claim_review_segments` 已缓存；全文上下文参与键，改一段仍可能使多段失效。用户背景引用须精确对应原文。 |
| 画面适配复核 | 核对编排画面能否支持该段表达 | 复用已有素材画面事实；需要审核的编排仍保留检查，失败回传具体原因。 |
| 配音、对齐与渲染 | 输入确认且通过审核的正文，产出真实音频、字幕及本地视频 | 配音 run 的状态与已有结果用于恢复；结果未知不得自动补发。渲染为本地步骤，不应重新购买已完成的内容生成。 |

当前 `_provider_calls` 记录模型和请求标识等元数据，不是完整 token／金额账本。保存需求会清理相关批次私有审核状态，但不会因此删除素材分析数据库缓存。不能宣称系统没有缓存，也不能宣称已经实现按金额限额。

## 后续优化顺序（尚未实施）

1. 补充逐请求用途、输入／输出／缓存 token、重试关联及计费状态；账单金额以平台结算为准。历史核对显示输入费用占大头，优先量化重复输入。
2. 按段落筛选必要证据，压缩重复背景；保留足够上下文，防止因省 token 导致人物和事实误配。
3. 评估将多段事实审核合并为可逐段追溯的结构化请求，并改进局部修改时的缓存依赖。先用固定资料验证等价，再接真实服务；不能用一次“整体通过”代替逐条证据。
4. 在能统计实际请求后增加全链路预算和停止提示。当前规划调用次数限制不能直接换算为人民币上限。

## 固定素材与本地验收

真实素材固定为 `优先使用素材2.mp4`（`asset_8ec7c037e09e43058381d2fb76b022b4`）和 `VID_20260828_130230.mp4`（`asset_8fddec6354db486b8e404ffea3aeb620`），沿用已确认的培训场景，不更换素材制造“通过”。此前40.352秒旧样片只作历史参考，不算本轮验收。

固定受众：物业保洁负责人。固定表达：这是清洁机器人培训现场，希望讲清培训时怎样对照实物认识部件、带着实际问题核对操作。固定引导：评论77，领取设备选型表。先确认现有材料确能支撑所选段落；资料不足直接记录，不补写学员姓名或学习成果。

人物身份的本地边界样例：假设用户输入“素材A中穿蓝衣的讲解者是测试学员甲，本次来了解部件”。这只是模拟资料，不能写成真实素材事实。应允许追溯该身份原文；应拒绝不存在的原文引用、把素材B另一人认作甲，以及“已经独立掌握全部操作”等推断。相关定向测试覆盖用户背景引用和缓存变化，不需要真实云调用。

本地检查包含：旧字段合并、主动清空、4000字限制、身份引用与缓存、事实审核原流程兼容、界面长输入及紧凑视口。构建通过和本地检查通过均不代表模型已实际遵循新表达框架。

## 充值后的最小真实试跑

1. 先核对历史结果未知请求，确认可恢复状态；不把新建批次当成绕过未知结果的方式。核实服务恢复前不试探收费调用。
2. 固定以上两份素材、一个受众、一个方向、最终一条视频；暂不扩大到批量300条或第二受众。记录试跑前账单时间、已有缓存和请求状态。
3. 生成三份，检查切入点、首份结构和事实来源；只对未通过部分有依据地修正，保存每次用途与结果。出现403、未知结果或预算耗尽即停，保留已完成部分。
4. 单选确认一份，检查审核、配音、字幕、结尾文字和完整视频；实际时长至少30秒，无填充。记录导出文件、请求标识及平台新增费用，不用文件数量掩盖失败调用成本。
5. 首条合格且费用可解释后再验收第二受众和批量变化。充值后执行属于后续工作，本轮不安排自动重试。
