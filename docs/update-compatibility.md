# 更新兼容范围与发布门禁

本轮核对的是源码协议，尚未以对应历史安装包完成升级。第二台 Windows 电脑的升级验收仍需单列记录。

| 起点 | 源码证据提交 | 协议与升级路径 | 实机状态 |
| --- | --- | --- | --- |
| 测试安装版 1.1.57 | `5c44723`，package.json version=1.1.57 | 已有 v1 完整安装包及 v2 增量更新；旧底座通过同目标版本 v1 完整包升级 | 待验收 |
| 测试安装版 1.1.75 | `6ce9e8a`，package.json version=1.1.75 | 已有 v1/v2；同上 | 待验收 |
| 测试安装版 1.1.77 | `e19ccd6`，package.json version=1.1.77 | 已有 v1/v2；兼容底座优先增量，否则同目标完整包 | 待验收 |
| 上述版本的非 development 版本 | 各提交 `src/main/cloud-config.cjs` | 历史配置直接返回 enabled:false，服务端无法远程启用；不属于可自动升级承诺范围 | 无可用在线入口 |
| 便携版、源码启动 | 各提交 `src/main/main.cjs` canInstall | 要求 Windows packaged 且在稳定安装目录；不支持执行安装更新 | 排除 |
| 其他未列历史版本 | 尚未逐版核对 | 不推断具备自动升级能力 | 未核实 |

三个已核对版本的 `cloud-maintenance.cjs` 都读取 `/v1/releases/test/latest` 与 `/v2/releases/test/latest`、验证签名，底座不兼容时转到 v1；`installOnExit()` 均返回 false。其历史完整更新助手不具备本轮新增加的完整程序备份回退，不能把新助手的恢复能力追溯承诺给首次升级的旧版本。

## 发布顺序

1. 在干净、已验收的同一版本提交构建并发布完整安装包，保留现有客户公告、签名、版本和提交检查。
2. 再发布增量包。门禁读取同频道 v1 签名清单，要求版本与本次目标完全相同；实际下载完整包并核对摘要及大小。缺失、旧版本、损坏或不可访问均阻止增量发布。
3. 上传完成、切换增量清单之前再次读取 v1，防止发布途中目标变化。服务端 `promote_components.py` 在 v1/v2 共享发布锁内再核对版本与完整文件哈希，消除最后一次读回与切换之间的并发窗口；此门禁需要随维护服务部署，本轮源码修改不表示已经部署。升级支持起点由 `desktop/release-upgrade-support.json` 维护；新起点需先核实协议，不能仅加版本号。

本轮选择同目标完整包作为旧协议过渡路径，不实现依赖多次重启的中间版本连跳。客户端仍优先下载适用的增量内容；完整包作为无法使用增量的已支持安装版本的兜底。保留 1.1.57 等旧底座支持期间，每个版本需构建并上传完整包，发布端还会下载一次校验，增加发布耗时和流量；不能通过删除支持起点绕过客户的升级路径。

`src/main/cloud-release-config.json` 通过 `build-portable-release.cjs` 的 src/main 递归复制进入安装版；测试、正式配置独立，正式频道默认禁用。启用正式频道前必须填入可信域名、公钥并建立该频道的已核实升级起点，发布脚本目前仍只发布测试频道。

## 本轮底座与隔离验证

1.1.78 是候选版本，底座版本同步为 1.1.78。更新助手与可信配置本次改变了底座指纹，不能沿用 1.1.77 底座做纯增量交付。`component-layout.json` 将程序恢复、更新存储、更新保留策略及其共享保留模块、可信配置归入 base，保持独立更新助手依赖同步；客户更新等待协调器仍属于 application。

已完成一次真实 Electron 进程的**完整更新路径隔离夹具验证**：`desktop/.build/update-process-tests/run-vGvC3o/result.json`，夹具从 1.1.77 升至 1.1.78，helper SHA-256 为 `8bc603f89b47d7355de04f2e04db38e0223fafca9aec2ca2fd7112b7770a1c58`。它运行实际更新助手，但安装器是测试时编译的无害 C# 程序，仅替换夹具 package.json；启动确认及业务资料不变均通过。**这不是正式 NSIS 安装器验收、不是用户安装版升级，也没有发布 1.1.78。**先前缺依赖失败的 `run-DDt8hq` 保留用于排查。后续 helper 改动需重新验证，不能沿用这个摘要的结果。

## 待验收

对三个历史测试安装版和新安装候选分别记录：版本/提交/文件摘要、资料与授权前后核对、单击更新、任务等待与取消、断网续传、安装失败与启动失败恢复。至少另一台电脑完成真实升级。没有入口的历史非测试版需独立迁移安排，不能以服务端发布成功表示该类客户可自动升级。
