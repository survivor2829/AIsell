# 内部更新标准

适用范围：开发者电脑及已安装测试版的内部测试用户。正式客户频道继续关闭。当前流程使用 GitHub Actions 做 CI，受控 Windows 构建机做打包和 CD；签名私钥与服务器 SSH 凭据留在构建机，不进入 GitHub 工作流或安装包。

## 每次更新的固定顺序

1. **完成改动并收尾。** 更新版本号、具体更新说明和 `PROJECT_STATUS.md`，核对需要同步部署的服务端接口。只提交本次确认的源码和文档，保留原素材、用户数据及回滚证据。
2. **提交并运行 CI。** 推送提交后，`Windows CI` 自动检查 Node/Electron 源码契约、维护服务和反馈接口、确认稿制作、制作聚合及请求用量，并构建测试/交付界面。失败先修复。CI 不访问真实微信、不调用付费生成、不读取发布私钥，也不发布客户更新。
3. **构建完整候选安装包。** 从同一干净提交执行下方 `release:internal`。该命令复用现有完整发布检查，重新构建 Python sidecar、Remotion 视频运行时及客户端，验证包内依赖、资源、隐私边界、版本和哈希，生成完整测试版 NSIS 安装器与版本清单。界面构建不能替代视频运行时构建。
4. **本机覆盖升级验收。** 保存编辑内容并结束任务，正常关闭应用；备份该 edition 的用户数据与旧安装包。安装新候选包，核对版本/构建号、图标、登录、配置和历史记录保留，以及本次改动的关键页面与功能。升级检查不自动授权对真实联系人发送消息或产生新的付费调用。
5. **部署依赖服务。** 新客户端依赖新增接口时，先按维护服务说明备份数据库、部署同版本服务文件，验证健康和明确的测试记录闭环，再发布客户端更新。
6. **发布已验收的同一个安装包。** 用户确认内部试用范围后，校验实际安装包与版本清单一致，使用 `publish:internal` 签名并推送测试频道。不得在验收后重新构建另一个包直接替换。客户端后台下载，正常退出后安装；旧客户端没有更新能力时，首次仍须手动安装测试版。
7. **核对发布结果。** 从公开更新端点读回并校验签名、版本、序号和 SHA-256；核对本机最新安装版，记录成功与未验收项。内部同事的电脑是否已完成安装，以该电脑状态或收到的运行记录为准，不能把服务器发布成功写成所有人已更新。

日常使用只需说清“本机验收通过，发布内部更新”。已有授权且版本与范围不变时，继续完成后面的步骤，不为每个命令重复询问；正式客户发布、额外付费调用、新增真实微信操作或重要数据清理仍按对应范围处理。

## 构建与发布命令

在 `desktop/` 执行。首次配置构建机时，参考 `build/internal-release-config.example.json`，将实际已有 Python、FFmpeg、Chromium 和对应来源记录的路径保存到 `.build/internal-release-config.json`。相对路径相对于配置文件所在目录；不要把密钥放进此文件。环境准备与安装依赖不是每次更新的重复步骤。

```powershell
npm.cmd run release:internal
```

产物为 `release/AI获客 V1.0版本-测试版-安装程序.exe` 及同名版本清单；本机构建记录位于 `desktop/.build/internal-release-test.json`。记录包含版本和运行时构建根目录，用于追溯，不是用户功能验收凭证。

本机验证并确认内部推送后：

```powershell
npm.cmd run publish:internal -- "../release/AI获客 V1.0版本-测试版-安装程序.exe" "../release/AI获客 V1.0版本-测试版-安装程序-版本清单.json" "../docs/releases/1.0.2-internal.md"
```

每次使用对应版本的更新说明文件。发布脚本要求具体更新说明，并校验测试频道 appId、版本、安装包哈希及大小。不能在更新说明中宣称尚未验证的能力。

如果安装后发现问题，保留现场、停止推广，基于修复后的代码增加版本号重新发布。客户端拒绝降低版本或序号，不通过手改服务器指针强行降级。旧安装包、数据库备份和签名历史按明确清理范围处理。

## 什么算完成

如果打包后仅调整 CI 编排或不进入包的自检夹具，可以保留已通过验收的安装包：记录包提交和最终 CI 提交，核对两者差异仅限这些文件，并验证已安装源码、运行时及 EXE 与包一致。发布仍从包对应的干净提交执行。应用源码、依赖、资源或运行时发生变化时必须重新构建及验收，不能用 CI 通过替代新版包验证。

| 状态 | 必须有的证据 |
|---|---|
| CI 通过 | 对应提交的 Actions 成功结果；本地命令通过单独记录 |
| 候选包通过 | 同一干净提交的完整打包检查、安装包版本清单及 SHA-256 |
| 本机可用 | 安装后的实际版本、数据保留及本次关键流程检查 |
| 内部 CD 完成 | 服务器读回有效签名清单，版本与已验收安装包一致 |
| 其他电脑更新完成 | 对应电脑已安装新版的实际确认或可信运行记录 |

CI/CD 不会自动证明所有微信场景、任意素材的视频质量或跨机器稳定性。完整商业发布的额外条件见 `README.md`、`PROJECT_STATUS.md` 和 `server/maintenance/README.md`。
