# 小玺AI获客未来落地规划方案V2.0

> 基于当前微信拓客、产品详情图和素材底座，规划下一阶段90天落地路线
> 生成日期：2026年7月31日

## 一句话结论

我们不是推翻现在的软件重做，而是在已经基本完成的微信拓客基础上，补上“统一自动流程”和“内容生产”两块能力。

先让主动触达、自动回复、朋友圈互动能够按顺序自动配合；再让系统可以把课程和日常素材做成短视频；最后由总部生成发布包，学员用本人手机发布，把线索接回微信继续跟进。

这份方案继续沿用V1.0的思路，重点回答三个问题：**现在有什么、下一步做什么、做到什么程度算完成。**

## 一、我们现在已经做到哪一步

当前项目不是从零开始，但也不能把页面入口或规划中的功能算成已经完成。

| 模块 | 现在已有能力 | 下一步要补什么 |
|---|---|---|
| 联系人同步 | 可以同步和管理微信联系人，为自动回复和主动触达提供名单。 | 在当前安装版和其他电脑上再做一次完整验收。 |
| 自动回复 | 可以发现新消息、生成回复，并在风险较高时提醒人工处理。 | 和主动触达真正联动：有新消息时先回复，回复后继续触达。 |
| 主动触达 | 可以创建联系人任务，支持分批执行、暂停、继续和记录结果。 | 接入统一任务流程，不和自动回复、朋友圈争抢微信。 |
| 朋友圈互动 | 点赞和AI评论已经有本机测试记录。 | 本次“打开软件就唤醒朋友圈”的源码问题已经修复，还要打新安装包做真实验收。 |
| 朋友圈发布 | 目前还没有形成完整功能。 | 做草稿、预览、人工确认、发布结果记录。 |
| 产品详情图 | 已经集成到AI获客，离线上传、排版、PNG导出和历史恢复可以测试。 | 完成覆盖安装和净机测试，再决定什么时候开放付费AI能力。 |
| 素材仓库 | 已经有原片原地索引、素材列表、任务恢复和成片中心底座。 | 增加转录、镜头分析、课程拆条、智能混剪和最终渲染。 |
| 渠道运营 | 已经明确“总部做内容、学员本人发布”的方向。 | 建学员、发布任务、发布回执、线索回流和数据复盘。 |

因此目前最准确的说法是：

> 微信拓客核心功能基本完成，但还要继续做安装版和异机验收；内容生产只完成了底座，真正的课程拆条、智能混剪和渠道分发还没有完成。

## 二、下一步总体方向

接下来分成四步，不一上来把所有功能都堆在一起。

### 2.0 微信自动获客流程

让现有功能真正按顺序自动配合：

```text
开始主动触达
→ 有联系人发来消息
→ 暂停在下一个联系人之前
→ 自动回复
→ 回复完成后继续主动触达
→ 到达设定时间或完成一批触达
→ 朋友圈点赞和评论
→ 朋友圈发布
→ 保存结果并进入下一轮
```

这些功能仍然各自独立。中间增加一个“统一任务中心”负责排顺序，避免某个功能出问题后把其他功能一起拖垮。

### 2.1 内容生产

先做最有把握的两种剪辑：

1. **课程拆条**：把10–40分钟课程找出完整观点，剪成多条30–90秒短视频。
2. **智能混剪**：把碎片口播、产品视频、图片和产品详情图，按照脚本自动组合成视频。

所有成片统一进入“成片中心”。AI脚本只是剪辑过程中的一步，不再单独做一个复杂的“脚本工厂”。

### 2.5 学员分发和线索回流

总部做好视频、封面、文案和标签，学员用本人手机确认发布。发布后回传链接或截图，短视频带来的私信、加微信等线索再进入现有客户池。

### 3.0 AI增长员工

等前面三步稳定后，再把内容生产、微信跟进、朋友圈运营、学员分发和数据复盘整合成一个可以持续运行的AI获客助手。

### 核心原则

先把一个账号、一条流程跑稳，再扩大到10–20个学员；先做到“稳定可用”，再追求“全部自动”。

## 三、90天落地路线

| 阶段 | 时间 | 主要目标 | 交付结果 |
|---|---|---|---|
| 第一阶段 | 第1–2周 | 收口现有版本。 | 解决启动唤醒朋友圈问题，生成新安装包，完成微信拓客和产品详情图验收。 |
| 第二阶段 | 第3–4周 | 建统一任务中心。 | 主动触达、自动回复、朋友圈互动可以排队、暂停和继续，不互相抢微信。 |
| 第三阶段 | 第5–8周 | 做课程拆条。 | 长课程自动转文字、选出片段，生成带字幕、标题和包装的竖屏初剪。 |
| 第四阶段 | 第9–10周 | 做智能混剪第一版。 | 选择碎片视频和图片，输入脚本后生成可预览、可替换镜头的初剪。 |
| 第五阶段 | 第11–12周 | 做发布包和小范围试点。 | 为10–20名学员生成视频、封面和文案，学员本人发布并回传结果。 |

如果一个人开发进度不足，优先顺序不变：**先微信自动流程，再课程拆条，再智能混剪，最后渠道试点。** 不为了赶90天，把没有验收的功能写成已经完成。

## 四、下一阶段各模块怎么做

可以把下一阶段理解成一条简单流水线：任务自动排队，素材进入系统，生成成片，学员发布，线索回到微信。

| 模块 | 通俗解释 | 第一版做到什么程度 |
|---|---|---|
| 统一任务中心 | 决定现在该主动触达、自动回复，还是做朋友圈任务。 | 一个功能占用微信时，其他功能等待；新消息优先；完成后自动继续原任务。 |
| 素材仓库 | 把课程、口播、产品视频、图片和产品详情图统一管理。 | 原片不重复复制，可以搜索、打标签、看处理进度。 |
| 课程拆条 | 从长课程里找出值得单独发布的完整观点。 | 每个课程给出3–8条候选，自动加字幕、标题、Logo和行动引导。 |
| 智能混剪 | 按脚本从碎片素材里选镜头并组合。 | 先生成可修改的初剪；素材不足时直接提示，不虚构内容。 |
| 成片中心 | 统一存放课程拆条、智能混剪和以后AI生成的视频。 | 可以预览、修改、重新导出，并生成封面和发布文案。 |
| 朋友圈发布 | 把审核通过的内容发到朋友圈。 | 第一版先做草稿和人工确认，记录成功、失败或结果不确定。 |
| 学员发布包 | 总部把成片交给学员发布。 | 视频、封面、文案、标签放在一个简单页面里，学员本人手机发布。 |
| 线索回流 | 把发布后的咨询和加微信客户记录回来。 | 记录来源平台、视频和学员，进入客户池继续自动回复和触达。 |

## 五、为什么现在不直接做全自动发布和上千账号

全自动发布和上千账号听起来很大，但不是当前最优先的目标：

- 平台登录、验证码和账号安全风险高。
- 当前真正缺的是稳定的成片能力，而不是帮人点击“发布”。
- 内容没有做好时，账号越多，重复内容和违规风险越大。
- 目前主要是一个人在开发和运营，必须先把小范围流程跑稳。

所以第一阶段采用：**总部生成内容和发布包，学员本人确认发布。**

等10–20个账号连续运行稳定后，再到50个；50个稳定后，再考虑300个。不能从一个账号直接跳到1,000个。

## 六、我们参考别人什么

不是照抄别人的界面，而是学习他们最成熟的能力。

| 参考方向 | 我们学习什么 | 落到小玺AI获客里怎么做 |
|---|---|---|
| Opus Clip | 从长视频里挑出值得发布的片段，并自动做好字幕和包装。 | 用在“课程拆条”，先把导师课程变成多条精美初剪。 |
| 开拍等AI混剪 | 根据脚本分析素材，自动选择图片和视频进行组合。 | 用在“智能混剪”，让碎片素材可以快速变成成片。 |
| 知了AI、谷小智AI | 把零散营销功能包装成一个AI员工。 | 用统一任务中心连接内容、触达、回复、朋友圈和复盘。 |
| Seedance等视频模型 | 根据提示词补充原来没有的画面。 | 先保留入口，等模型、API价格和授权稳定后再接入。 |

## 七、每个阶段的验收标准

| 阶段 | 做到什么才算完成 |
|---|---|
| 启动修复 | 打开AI获客时不自动前置微信、不打开朋友圈；原来的进度和未来定时仍然保留。 |
| 微信自动流程 | 新消息到来时主动触达可以安全暂停；回复完成后只继续未处理联系人；任何结果不确定都不重复发送。 |
| 课程拆条 | 至少用5个10–40分钟课程测试；每个课程给出3–8条候选，大部分不在半句话中截断。 |
| 智能混剪 | 至少完成20个图片和视频混合项目；用户替换镜头或修改字幕后可以稳定重新导出。 |
| 成片质量 | 输出9:16视频，带字幕、标题、品牌信息和行动引导，运营人员只需做少量修改。 |
| 学员发布 | 10–20个账号连续试点4周；不收密码，学员能收到发布包并回传发布结果。 |
| 线索回流 | 能看出线索来自哪个平台、哪条视频和哪个学员，并进入微信客户池继续跟进。 |
| 数据复盘 | 能看到发了多少视频、带来多少咨询、加了多少微信、后续跟进到哪一步。 |

## 八、最终形成的产品故事

### 产品定位

小玺AI获客不是单纯的微信群发工具，也不是只会生成一条视频的软件。

它是一套“内容获客 + 微信承接”的AI增长助手：前面帮助总部和学员持续生产内容、获得咨询；后面用自动回复、主动触达和朋友圈运营继续跟进客户，并把每一步的结果记录下来。

对客户可以这样讲：

> 客户只需要提供课程、口播、产品素材或简单文案，小玺AI获客帮助他生成可发布的视频和文案；客户本人确认发布后，线索回到微信，再由系统继续接待和跟进。

## 九、近期不要做的事

- 不急着做1,000个账号，先把10–20个账号跑稳。
- 不收学员账号密码、验证码、Cookie或设备登录状态。
- 不承诺所有平台都能自动发布，先做好成片和发布包。
- 不急着接Seedance和数字人，先把现有真实素材剪好。
- 不把AI脚本单独做成复杂板块，脚本只是剪辑中的一步。
- 不重写已经能用的联系人、自动回复和主动触达功能。
- 不把页面入口、规划方案或自动检查通过写成真实业务已经验收。

## 十、总结

接下来最正确的路线是：

```text
先修好并验收现有微信拓客
→ 让主动触达、自动回复和朋友圈能够自动配合
→ 用课程拆条做出第一批精美短视频
→ 再做碎片素材智能混剪
→ 总部生成发布包，学员本人发布
→ 把线索接回微信继续跟进
```

90天内最重要的不是做一个看起来很大的平台，而是做出一条真实可演示、能持续运行的流程。

第一优先级是新安装包和微信自动流程；第二优先级是课程拆条；第三优先级才是智能混剪和学员分发。这个小闭环跑通以后，再进入更大规模的AI增长员工阶段。
