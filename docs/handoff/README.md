# 双模型协作流程（长期有效）

原则：简单的事简单做，复杂的事认真做，不用流程去治流程。

**分工**：Claude 规划、审查、写卡、维护 `PROJECT_STATUS.md`；Codex 按卡实现、自检、写结果；用户定优先级、拍板、真机验收、批准发布。

## 风险分级

按**实际改动的文件**取最高一级；只升不降，中途碰到更高级别的文件就立即升级。

| 级 | 典型文件 | 流程 |
|---|---|---|
| 高 | 微信/抖音发送链路（`desktop/rpa/**`、`touch-*`、`auto-reply-*`、`moments-*`、`contact-sync-*`、`keyword-acquisition*`、`douyin-*`、`wechat-*`）；付费调用（`product-video-*`、`digital-human-*`、`provider-gateway*`、`server/**`）；密钥；用户数据迁移或删除；发布与更新 | `-task` / `-result` / `-review` 三份文件；Claude 在独立 worktree 复跑、证明新断言在旧代码上失败、做对抗审查 |
| 中 | 其他主进程和内容引擎业务逻辑、界面交互、自检框架、CI | 一页短卡（目标、范围、验收），卡末追加结果和审查 |
| 低 | 纯文档、文案、样式、注释、只新增测试 | 不写卡，Claude 可直接改 |

## 通用要求（各级都适用）

- Codex 只改卡上允许的文件，对不上先写异议；不自行合并、不发布。
- 新增断言必须在旧实现上失败；验证走真实入口。构建、自检、真实验收分开报告，没验证的不写成已验证。

## 分支与授权

- `main` 是主线，只从 `main` 发版。
- 每个任务从 `main` 拉短分支：Codex 用 `codex/<任务>`，Claude 用 `claude/<任务>` 并在独立 worktree 里改。同一工作区同一时间只有一方写。
- 审查和 CI 都通过后合并进 `main`，并删除这条分支。只删已合并的分支。
- **长期授权**（用户 2026-09-24）：审查和 CI 都通过后，可以推送分支、提 PR、合并进 `main`、删除已合并的分支。
- **仍需逐项问用户**：发布、真实微信/抖音操作、付费调用、服务器部署、凭据变更。
- **过渡期**：第一批（T1c、T4、T2、B0、T5）在 `codex/fix-apimart-gateway-transport` 上收尾；全部通过后合进 `main`、删已合并分支，并把 `PROJECT_STATUS.md` 精简为一页"当前状态"（历史只挪到归档，不删）。

## 防臃肿

- **上限**。"一页"指不超过 60 行、3,500 字符，用 `wc -lm` 量：
  - `AGENTS.md`、本文件、`PROJECT_STATUS.md` 的"当前状态"，各不超过一页；
  - 积压任务卡不超过两批；
  - 分支存活不超过 7 天。
- Claude 每开始一批任务时顺手核对一次。超标只报告并给精简建议，不挡干活。
- 每发一个版本回顾一次流程。删规则、改规则、归档文档，都先列出来问用户。
- 新规则必须来自真实踩过的坑；加一条之前，先看能不能删一条。
- 能删的只有流程步骤。代码里的安全保护（身份核验、结果不明不补发、付费不重复提交）和对应的测试，永远不删。
