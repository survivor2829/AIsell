# Claude ↔ Codex 交接目录

分工：Claude 负责规划、审查、根因定位、写任务卡、复核验证、更新 `PROJECT_STATUS.md`；Codex 负责按任务卡实现、跑自检、写交付说明。两边共同遵守仓库根目录的 `AGENTS.md`。

## 每个任务三份文件

| 文件 | 谁写 | 内容 |
|---|---|---|
| `<日期>-<任务>-task.md` | Claude | 目标、证据（文件:行）、允许改动范围、禁止事项、验收命令与期望结果、需用户本人验收的项 |
| `<日期>-<任务>-result.md` | Codex | 改了什么、验证命令和实际输出、未验证项、对任务卡的异议（确认 / 证伪 / 证据不足） |
| `<日期>-<任务>-review.md` | Claude | 结论只有三种：通过 / 打回（附具体问题）/ 需用户拍板 |

## 规则

- Codex 在独立分支 `codex/<任务>`（或 worktree）上实现；同一工作区同一时间只有一方写。
- 只改任务卡允许的文件；发现任务卡与代码现实不符，先在 result 里写异议，不自行扩大范围。
- 不自行合并、提交到 main、发布。付费调用、服务器部署、真实微信/抖音发送、发布都需用户逐项授权。
- 新增断言必须在旧实现上确定性失败；验证要走真实入口，不以手工调用内部函数替代。
- 交付说明把构建、自检、真实验收分开写；未验证的不写成已验证。
