# T1c【P0】称呼：只认整条备注的固定格式（取代 T1b）

分支：继续在 `codex/fix-salutation-extraction` 上追加提交。实现时，`contactSalutation` 整体替换为本卡规则，T1b 的姓名段推断逻辑全部删除。

## 为什么再改（Claude 的反思）

T1、T1b 都是"从随手写的备注里猜哪个字是姓"。三轮对抗审查、约 1500 条样例表明，这条路补不完：
- "厂家经理""物业方经理""省代总"会把"家""方""代"当成姓；
- "李经理(王总)""老板娘-王总""来源：王总"会叫错人；
- "鱼老板""米老板"这类按生意起的外号，会把"鱼""米"当成姓；
- "东方""南宫"会把品牌、地名当成复姓。

T1c 不再解析句子，**只有整条备注完全符合固定格式才叫尊称，其余一律只说时间问候**。这个规则已由 Claude 用原型验证：对三轮审查报出的 155 条叫错样例，153 条返回 generic，剩余 2 条列在下方"已知残余风险"。

## 规则

1. **只看备注（remark）**。昵称由客户自己起，一律不用；备注为空就返回 generic。
2. 预处理：
   - 先删除带圈字符和括号字符（`U+3200–32FF`、`U+2460–24FF`，例如 ㊎），再做 NFKC，最后去掉首尾空白。
   - 这个顺序是必要的：NFKC 会把 ㊎ 转成"金"。
3. **关系词一票否决**。备注中出现以下任一词，直接返回 generic：
   助理 秘书 司机 老公 老婆 爱人 太太 夫人 家属 儿子 女儿 介绍 推荐 朋友 同事 亲戚 的 媳妇 老板娘 嫂 来源 渠道 引荐 邀请 跟进 业务员 销售 客服 跟单 经办 录入 归属 上级 领导 决策 拍板 下属 员工 财务 会计 出纳 采购 前台 对接 店员 徒弟 学生 家长 保姆 阿姨 保安 文员 仓管 父 母 爸 妈 舅 侄 甥 婿 姐夫 妹夫 表 岳
4. **整条备注必须完整匹配**（正则两端锚定 `^…$`）：
   `[机构前缀 + 分隔符]` + **1 个汉字** + 职务 + `[分隔符 + 电话]` + `[分隔符]`
   - 职务：`总经理|总监|总|经理|主任|老师|老板`，其中"总经理"输出为"总"。
   - 机构前缀（可选）：1–24 个汉字、字母或数字，并且必须以下列机构词结尾：
     公司 集团 科技 商贸 实业 中心 工作室 门店 店铺 工厂 厂 店 部门 部 团队 物业 酒店 医院 学校 大厦 广场 有限 股份 超市 商场 银行 小区 园区 分公司 总部 办事处 事业部 项目部
   - 机构前缀和人之间**必须**有至少一个分隔符。分隔符包括：空白 `, ， 、 ; ； : ： _ · / |`，以及各种横线（`\p{Pd}`、`−`）。
   - 电话（可选）：`+`、数字、空格、`-` 组成，至少 6 位。
5. 那 1 个汉字必须属于**常见前 100 姓**。字表沿用 T1b 的 `TOP_SURNAMES`。不再使用复姓表、"小/老 + 姓"、两字或三字人名。

参考实现（Claude 的原型，已按上面的样例验证，可直接采用或改写）：

```js
const RE = new RegExp(String.raw`^(?:([一-龥A-Za-z0-9]{1,24}?(?:${ORG_END}))${SEP}+)?([一-龥])(总经理|总监|总|经理|主任|老师|老板)(?:${SEP}*\+?\d[\d\s-]{5,})?${SEP}*$`, "u");
// SEP = String.raw`[\s,，、;；:：_·/|\p{Pd}−]`；ORG_END 为第 4 条的机构词用 | 连接
```
