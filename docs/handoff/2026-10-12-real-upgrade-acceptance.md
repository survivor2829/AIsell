## 范围与发布门槛

任务分支 `codex/upgrade-compatibility-acceptance`；正式客户频道和付费搜索保持关闭。用户要求真实安装、启动确认和正式安装包失败回退通过后再合并发布，不能以下载成功或模拟安装器替代。本轮不要求用户在其他电脑运行脚本或覆盖安装。

## 独立 Windows 实装

本机 Windows Sandbox 启动返回 `0x800706d9`，相关服务正在运行，但当前令牌不能查询 Hyper-V 管理信息。一次管理员请求被 Windows 返回取消，没有执行特权诊断或改动系统安全设置。用户随后授权管理员确认；因用户当前不在电脑前，本轮改用 GitHub 托管的独立 Windows 验证机继续，不依赖现场确认。

`desktop/scripts/update-install-acceptance.ps1` 只允许 GitHub 托管 Windows 或 Windows Sandbox 身份，安装原始 1.1.64，再通过正式官方助手安装官方 1.1.86。使用合成回执与运行时 junction，不上传本机客户资料。目标必须安装成功并收到 1.1.86 启动 ACK。

原始安装包 SHA-256：`df85caee5c47cd4eb1ccc6bcbac3d844b737aa653b6ab9c488f4fb973bb8209a`。目标官方包：`c7b3c4b51e09276dbe1602a71e2fb35b225c4e2c991022b96671927db308a8ff`。助手：`9f113fc437afad04712e62f0bf5a321cdb53f922c9dce902258fc154480e175d`。

原包和助手保存在未发布草稿 `acceptance-original-64-20261012`，不是客户更新发布。目标包从官方 HTTPS 获取，固定 CA 并复核摘要。GitHub 读取未发布草稿需要写权限，仅手动验收 job 获取该权限，没有发布步骤。

验收工具首次遇到草稿读取权限不足，随后遇到 UIAutomation 控件不支持 InvokePattern、按钮类型无法定位；均未执行新版安装，不能当作产品安装失败。已在本机只读核对真实 WinForms BUTTON 句柄，改用按进程核验的原生按钮消息。

正常升级与故障验收使用不同并发组。故障组分别中断正式安装器（观察到程序已发生变化后）、中断新程序启动，要求恢复旧程序的逐文件摘要、版本选择记录和原回执，并重新打开旧程序。这是隔离机器上的受控实际进程故障，不等同已复现客户电脑的 EPERM。

原正式助手在独立验证机成功执行原始 64 安装，但在交接安装前停止；运行 `38289563337` 记录故障 `update_failed`，C 盘仍有约 28.4 GiB 可用，不能归因为空间不足。已增加仅包含故障类别及模块行号的本地诊断，不记录原始异常文本、业务内容或凭据；新诊断助手暂存在未发布草稿，SHA-256 `83d9fe9eee4fc6a246b95e00e042c5547dacf6fb607b3bbf4d4e9ae7491b5aba`，不是正式分发助手，也未改变更新频道。

进一步定位运行 `38290803526`：`detecting` 阶段，子进程 `childKilled: true`、`signal: SIGTERM`，没有安装 job。这对应 `processRows()` 的 15 秒 PowerShell/CIM 查询超时；先前的安全错误码过滤把子进程超时合并为 `update_failed`。将官方助手及安装助手的同类进程查询期限调整为 60 秒，超时明确记录 `update_process_snapshot_timeout`，不跳过进程身份或占用检查。新修复候选助手 SHA-256 `fdc4abd9417739bab56d3ae21137a3dd4b9cd19496bc719c62bc6e88c39928aa`，仅用于未发布验收，尚未代替正式分发助手。Electron 备份定向自检通过；实际旧版实装结果仍待补验。

运行 `38291486892` 已通过此前系统检查并启动真实安装助手，随后助手报告 `update_request_not_committed`。进程证据显示父协调器仍在执行身份复核查询，而助手的 35 秒授权等待已到期，安装尚未开始。统一由现有安装助手提供进程快照，删除协调器的重复实现；授权期限按两次进程查询上限加原 35 秒余量计算（155 秒）。备份定向自检再次通过。候选助手 `3e4063c9857bc34e1c7dc33022417f8b3f8f44bd45fca9d6d5cb745be198a251` 正在运行 `38292507738` 做真实实装，尚未分发。

普通源码 CI `38288777039` 及修复后的 `38293048871` 均通过：源码自检、运行与密钥边界、测试与交付界面构建，以及服务/内容检查。后者覆盖当前更新源码，随后只有验收脚本和文档改动。实际安装及故障结果见下，构建结果不替代实装。

### 定向审查

按项目精简执行的偏好，本轮采用定向人工审查，不额外启用多模型评审流程。范围为本轮更新源码、CI 和验收脚本：核对可信载荷先验签再执行、查询期限与授权期限一致、两次身份核验保留、取消/未知状态不自动提交，以及真实 NSIS/ACK/回退断言。不改业务任务、密钥和发送逻辑。未发现本轮引入的阻断性问题；错误收集在空 jobs 目录下改为安全枚举，避免诊断失败覆盖原异常。

已知既有说明限制：安装器中断和启动中断恢复成功共用 `update_start_rolled_back`，界面文案会说“新版本启动失败”，不区分本轮具体故障发生点。本轮由 `fault.json` 的实际中断阶段及状态回执保留验收依据，不将该文案当成根因证据；此项不是本轮新引入的问题。
