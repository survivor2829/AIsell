# T10a【P0·高】搜索结果识别：修 r008 的根因（判定逻辑）

分支：`codex/fix-search-recognition`，从最新的 `codex/fix-apimart-gateway-transport` 拉出。T5 返工与本卡都会改 `wechat_search_result_resolver.cjs`：T5 只加证据输出，本卡只改判定逻辑。两者谁后合并谁负责变基。

## 根因（Claude 组织的只读排查已确认，约 95%）

- 用户看到的现象：搜索微信号后，下拉框里明明有这个联系人，程序却显示"正在准备执行下一步"，过一会儿就跳过。
- 提交 `90a0564`（9-19 19:31）在 `wechat_search_result_resolver.cjs` 按微信号搜索的分支里加了一行提前返回（基线约第 400 行）：`if (!webSearchCandidates.length) return reject("search-r008")`。从此"读到'搜索网络结果'分界"成了唯一的通行条件，名字分区标题、"微信号：<查询>"这些正向证据都不再看。
- 分界必须整行完全匹配，两边的写法还不一致：
  - PowerShell 端（`wechat_window_driver.cjs:1601` 的 `networkSearchPattern`）：行首只容忍 0–2 个非字母、非十进制数字的字符（`\p{Nd}`）；
  - JS 端（resolver 的 `isNetworkSearchLabel`，约 :190）：去前缀时用的是 `\p{N}`；
  - 两端都不容忍行尾多余字符和错字。
- 本机真实观测里，放大镜图标被 OCR 读成过"〕"和"0"。灰色小标题也出现过掉字、错字（自检用例"最常使用"被读成"常便用"）。
- 离线回放结论：用本机 9-20 那份真实观测造 7 种"分界读偏"（删掉分界、前缀读成 0 / Q / 口、错 1 个字、行尾多 1 个字、分界被推出截图区），`846a712`、`1fda2b4` 都能选中联系人；`90a0564` 及之后的版本全部返回 r008。

## 要做（只改判定逻辑；安全原则 S1–S5 一条不放松）

**安全原则**
- S1：分界及其下方的行、含"网络查找"的行及其同一视觉行、只有查询词的回显行，一律不点。
- S2：本地联系人区恰好 1 个好友才点。分界多于 1 个判 r011，"微信号"行多于 1 条判 r007。
- S3：必须证明候选属于本地联系人区。
- S4：微信号本身永远不做模糊匹配。
- S5：同一次尝试里多次观测必须一致，不一致就拒绝。

1. **F2 分界识别有限容错，JS 和 PowerShell 用同一套语义。**
   - 行首最多去掉 2 个**任意**字符（数字、字母、"口"、"〇"都算），剩下的必须等于标签（可带查询词后缀）。
   - 仅对"搜索网络结果"允许错 1 个字（编辑距离 ≤1）。前提是这一行和分区标题左对齐（±8px）、行高相近（±30%），并且行内没有别的文字。
   - 同时满足的候选多于 1 个仍判 r011；只有 1 个时，取最上面那个作为分界。
   - 修掉 `\p{Nd}` 与 `\p{N}` 不一致的问题：两端对同一张字符串表的判定结果必须完全相同。
   - 这样放宽只会让分界上移、本地区变小，或者触发拒绝，不会让不该点的行变成可点。守 S1、S4。
2. **F3 同一次尝试内补读，不重新输入。**
   - 没读到分界时，先把同一张截图放大 3 倍、做灰度和对比度拉伸，再识别一次。
   - 还不行就隔 0.6–1 秒再截一次图。只有两次观测里本地行的位置一致（±2px）才合并证据，不一致就拒绝（S5）。
   - 在 result 里记下补读救回了多少次。
3. **F4 没有分界时唯一允许的通行路径**（替换约第 400 行的提前返回）。以下全部满足才选中：
   - 能读到联系人分区标题（`isLocalContactSection`）；
   - 标题下第一个结果是"名字行 + 紧接着一行以'微信号'开头、规范化后与查询词完全相等（`labelledWechatId`）"的两行结构；
   - 整个截图区里以"微信号"开头的行恰好 1 条；
   - 这个好友下方紧接着是分区标题、网络查找行、回显行或下拉框底部，而不是第二个好友；
   - `hasNameConflict` 不命中；
   - 点击位置是**名字行**的中心。
   - "网络查找微信号：xxx"那一行不以"微信号"开头，天然被排除。守 S2、S3、S4。
   - 其余情况照旧返回 r008。
4. **F5 补强**：含"微信号"但不以它开头的行、含"查找"的行，连同它们的同一视觉行，一律屏蔽。按微信号搜索时，只有一行文字的"本地行"不作为通行依据，因为真实的好友行一定有第二行。
