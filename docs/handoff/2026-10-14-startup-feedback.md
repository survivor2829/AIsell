# 启动反馈首轮改进

基线：`31d488c`，任务分支 `codex/startup-feedback`。只处理启动反馈，不展开后续 AI 专家和素材交互改造。

## 改动

- 安装版取得单实例锁后，先显示本地、无网络依赖的启动窗口，再执行原有文件完整性校验；更新助手和发布 smoke 不显示此窗口。
- 重复启动在校验期间唤起启动窗口，主窗口 ready-to-show 后唤起主窗口；主窗口准备好才销毁启动窗口。
- 保留校验失败回退，显示回退结果；窗口加载失败和主进程异步初始化失败明确报错退出。用户关闭启动窗口后不再继续提交待启动标记。
- 增加 bootstrap、校验开始/结束/失败、启动窗口与主窗口可见的阶段计时，复用已有诊断日志。

## 已验证

- bootstrap 与 startup-feedback 定向自检：提前反馈、原版本优先级、隔离 smoke、校验失败回退、重复启动、窗口交接、取消及主窗口加载失败通过。新增提前反馈断言在旧 bootstrap 上失败。
- `npm.cmd run build:test`、主进程语法检查、diff 空白检查通过；构建保留原有 Vite 大 chunk 提示。
- 隔离 Electron 实测使用真实第二进程启动，HTTP/HTTPS 被屏蔽：启动窗口可见、无重复窗口、交接后启动窗口销毁、最小化后重复启动恢复均通过。隔离样本启动反馈 364ms，不代表完整安装版耗时。
- 启动窗口截图已查看；Impeccable 静态检查返回空列表。独立只读审查发现的初始化异常缺口已修复，复审无新增阻断发现。
- 隔离证据位于 `desktop/.build/startup-feedback-acceptance.json`、`startup-feedback.png`，不含用户业务数据。

## 完整包验收待完成

本次没有覆盖用户正在使用的安装版，没有发布。完整安装包尚未构建与安装验证；功能分支的源码检查和隔离窗口实测不替代这一步。首次交付必须更新稳定启动入口，不能仅发组件增量，见 `docs/internal-release.md`。

完整包就绪后，在安装目录核对 bootstrap、startup-feedback、startup-timing 与对应 main；从快捷方式分别验收首次和再次启动，记录启动反馈/登录页可见/可交互三段耗时；启动中重复双击只唤起已有窗口；断网仍显示反馈；退出启动窗口不能继续打开主界面。损坏组件回退只在隔离候选目录验证，不修改用户当前更新目录或历史数据。
