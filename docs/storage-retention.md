# 程序、更新与构建保留规则

## 客户端更新

- 原安装底座保留；组件只保留当前激活版、上一版和最新待安装候选。
- 新候选先登记保护，再下载；完整准备成功才替换上一待安装候选。成功启动并收到回执后刷新当前/上一版保护。较早的受管组件目录及不再引用的归档自动回收。
- 下载失败保留最新目标可续传归档，下一目标会回收受管旧下载，删除本次解压暂存副本。只登记实际新建的文件，复用旧文件不会接管其所有权。清理在工作线程执行，失败只记录告警，不把更新成功改成失败。
- 完整升级前备份业务数据，排除更新运行时与助手副本。成功启动后，自动保留最近一组由新机制登记的完整升级数据备份；安装或启动失败的备份留作恢复证据。

## 开发构建与本机验收

- 组件构建保留最近两组通过校验的候选程序、归档和描述文件；使用中的增量底座额外固定保护，共用归档只存一份。
- 完整便携程序、ZIP和安装器分别保留当前输出及一组受管回滚输出；三个大型运行时各保留最近两组受管缓存。
- 本机升级前先保存文案、关闭应用，再运行 `desktop/` 下的统一备份命令：

```powershell
npm.cmd run backup:local -- --program "原安装目录" --profile "该edition日常数据目录" --output-root "D:\OpenAI\LocalInstallBackups\test"
```

命令根据日常数据目录的激活记录选择实际运行的完整程序，保留最近两组自己创建的备份。业务素材、成片与费用回执备份保留，更新缓存不混入数据备份；备份失败只回收本次不完整副本。Windows备份目录只授予当前用户、SYSTEM和Administrators访问。

不要再为每次验收人工复制完整用户目录，也不要创建新的 `.local-rollback-*` 目录。首次执行不会接管或删除旧备份。

## 历史内容和生效边界

- 所有自动回收仅针对所有权台账登记的生成物。已有旧目录、唯一原素材、已认可成片、日常用户数据、费用回执、聊天记录和用户手工归档不按名称或年龄自动删除。
- 两个已验收的完整回滚程序及 `D:\OpenAI\ReleaseBases` 不由本次规则主动清理。旧工作树、历史全量备份仍先列候选再确认。
- 开发侧规则随源码使用；客户端规则需包含本次修改的新安装版才能生效。不得把源码检查通过写成旧安装版已自动启用。
