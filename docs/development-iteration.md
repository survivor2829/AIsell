# 快速迭代与减少返工

目标是缩短拿到可用结果的时间。先稳定现有链路，再逐步打磨精准获客、企微助手和 GEO；不把商机验证作为开发前置，不全面重写架构。

## 每轮工作

在已有任务或交接记录中写四项：问题及发生阶段、预期行为、修改边界、验收证据。先复现，不能复现就列假设和缺失证据。连续两轮修改未解决时停止试改，重新核对设备、版本、日志与真实运行入口。不得把无法复现写成修复成功。

一个负责人、一个集成工作树负责本轮修改；调查与只读审查可并行。高风险改动由另一审查者读取固定差异、基线、需求和验证结果，检查费用、恢复、数据、安装失败路径；只采纳有依据的发现，修正后只复查相关部分。不要求购买特定模型，不允许两个工具同时改同一工作区。

## 分层反馈

| 改动 | 最小有效反馈 |
|---|---|
| 文档、规则 | 内容、链接与 diff，不构建应用 |
| 文案、布局、交互 | `desktop/` 下 `npm.cmd run desktop` 热更新，查看受影响页面；交付前一次相关构建 |
| 业务、IPC、服务 | 复现原故障、定向回归、真实 Electron 入口冒烟前置 |
| 费用、恢复、数据、更新 | 独立只读审查、隔离数据、对应失败与恢复场景 |
| 内部发布 | 沿用现有 CI 和发布门禁，默认组件增量，不以普通构建失败为由转整包 |

开发预览、源码检查、候选包、本机安装、异机可用分别报告。共享状态的桌面验收串行执行。付费调用和真实发送只按具体授权；优先历史结果与隔离回放。输入未变、没有新增风险的已通过检查引用原证据，不反复运行；复用时核对相关源码和依赖，证据不能跨变化沿用。CI 门禁不因本标准删减。

## 时间与空间

任务记录按定位、修改、返工、验证、构建、上传、等待用户列出起止时间或命令实测耗时。并行时间不能直接相加；等待计入总历时并注明原因。未测量填未知，未执行标明未执行，不补造历史耗时。

构建发布复用 [空间记录](development-storage.md)：每个阶段新增单调时钟累计 `elapsedMs`、相邻观测间隔 `stageElapsedMs`、本次扫描耗时 `measurementMs`；报告总 `elapsedMs`。间隔包含命令、调度及记录开销，不冒充 CPU 时间或纯编译时间；嵌套报告不相加。扫描若成为瓶颈，先据 `measurementMs` 调整观测范围，不能用猜测关闭检查。

依赖未变不安装，运行时未变复用指纹缓存，不为预览复制完整安装目录或业务资料。本轮成功临时副本按现有归属机制回收；失败保留必要证据。历史清理须另核唯一内容和引用并确认，当前激活版本、验收候选、引用底座不得自动回收。

下一次获准发布记录阶段峰值、清理后净增量、业务数据增长、上传量、本机下载量和远端 CI 产物；重叠目录、不同设备分开。磁盘剩余空间变化不等于版本垃圾。本标准不授权发布或历史清理。

## 样板与交接

### 当前工作树的正常开发入口

在 `desktop/` 运行 `npm.cmd run desktop`。缺失的 JS 包可通过本工作树忽略文件 `.build/development-dependencies.json` 指定 `{ "desktopDir": "已有完整依赖的 desktop 绝对路径" }` 补缺；启动器与非安装版 bootstrap 都加载它，并校验两侧 package-lock 内容一致。它是后备搜索路径，不覆盖现有包，也不安装或修改共享依赖。锁文件变化时先同步依赖来源，不能跳过校验。

当前 1ac9 后备配置引用 0054 的 desktop（其 node_modules 实际解析到 a15e）；现有 node_modules 仍引用 Desktop 工程。14 个直接依赖和开发依赖已核对实际版本与当前锁文件一致。上述引用目录不能作为无主缓存删除。

产品详情图开发入口直接运行当前源码：优先使用 `XIAOXI_PRODUCT_DETAIL_DEV_PYTHON` 或 `.build/product-detail-venv/Scripts/python.exe`，检测 Python 版本及必要库，缺依赖则继续寻找候选或回退经过来源校验的运行时。1ac9 的 venv 链接复用 Desktop 工程既有环境；不复制、不重新安装。安装版仍使用包内 exe。Vite 缓存固定在本工作树 `.build/vite`，不写共享 node_modules 缓存。

此配置用于正常全量主进程/IPC/已保存用户资料的开发入口，不是简化预览。清理工作树或共享环境之前必须检查这些引用。启动器允许通过 `npm.cmd run desktop -- --remote-debugging-port=端口` 临时开启本机验收；平时无需调试参数。

产品详情图样板：启动 → 编辑 → 原任务查询恢复 → 结果 → 下载 → 服务重启后历史。检查启动失败、恢复未就绪、费用取消、模块切换；分别记录真实服务、隔离回放和历史证据，不能混称完整线上验收。其他模块给出可用／失败／未验证清单，微信发送和异机验收另安排。

收尾复用一份交接：基线和差异、已验证、未验证、耗时、返工次数及原因、空间与仍占用的预览目录、下一项优化。以实际瓶颈选择下一步，不按测试或工具数量衡量产出。
