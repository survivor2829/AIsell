### 可以具体评审的清理候选

`cleanup-candidates.json` 列出 **90 个明确路径，合计约 7.77 GiB**：仅来自 a15e 的 30 次成功隔离更新验收。逐项检查了 `fixture-marker` 与 `result.json` 的 `ok: true`，候选限定为测试 profile 下的 `components/program-backups`、`components/generations`、`update-helper-profile`。没有当前运行进程位于这些测试目录，也不属于当前构建记录登记的底座／候选。

这些是测试用程序副本及缓存；结果、日志、registry 与测试业务资料不在候选内。**本轮没有删除历史候选，需确认这份具体清单后执行。** 执行前须再次核对进程和引用，实际释放量以删除后分区可用空间变化为准。

a15e 的更新助手目录另有约 19.16 GiB、旧版升级验收约 6.07 GiB，混有成功、回退、失败及交付记录，不计入上述 7.77 GiB；尚不能承诺全部可释放。

## 已改掉的持续增长点

更新验收原来只清理 installed 和 helper-runtime，测试 profile 的程序备份继续累积，每次约 265 MiB。本次扩展原有成功清理名单，不另建清理机制，不清理真实用户备份，失败仍保留现场。

实跑一次当前代码的隔离更新验收：1.1.92 → 测试夹具 1.1.93，成功、资料不变；所有指定可重建副本消失，留下 **47,528 字节** 的结果及证据。这里的 1.1.93 是测试版本号，不是发版。

构建和发布入口增加空间账，详见 [开发与发布空间记录](../development-storage.md)。本轮 renderer 输出约 108.59 MiB；第一次记录相对已有输出净增 48,329 字节，后续构建复用同一目录，不按次数额外存一整份输出。这不包含图片源文件、验收 profile 等，也不能冒充本轮总增量。

## 一个版本到底占多少

1.1.92 已有交付记录中，完整安装包 616,405,605 字节（约 588 MiB），本次本机增量下载 155,834,013 字节（约 149 MiB）。两者不是开发全过程的总占用。一个版本还可能产生运行时、候选组合、临时解包、安装备份和验收副本；有些共享，有些被回收。

现有数据不能回推出每次开始前的磁盘状态。以后用新增阶段记录给出观测峰值和清理后净增量，成功发布返回实际上传文件量，再用本机更新回执补下载量。GitHub 云端 CI 单独统计；没有证据的值保持未知。本轮没有为凑统计额外打整包、部署或发布。
