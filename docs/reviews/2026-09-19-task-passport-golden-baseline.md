## 通用判定

- 每条命令退出码为 0，且原有断言全部通过。
- `sent_verified`、`not_attempted`、`outcome_unknown` 三种结果不得互相转换。
- 结果不明时不得自动补发；明确未点击时不得记为已发送。
- 护照写入失败只允许缺少观测记录，不得改变原任务结果。

## 实机暴露问题与根因修正

1. **任务与诊断绑定错误**：部分诊断使用脱敏后的对象值拼接任务目录，可能产生 `task-<hash>` 假目录。现由工作流把真实任务 ID 与 trace ID 显式绑定；第二轮精准触达只写入正确任务目录，没有再生成假目录。
2. **失败截图错窗及裁切**：异步取证若只抓当前前台窗口，会在故障发生后截到别的窗口；PowerShell 5.1 中 `$pid` 又与只读 `$PID` 冲突。现优先使用失败现场 `expected_hWnd`，重新核验其进程属于微信，并启用 Per-Monitor V2 DPI 感知。实测截图由裁切的 `1120×760` 恢复为微信物理窗口 `1400×950`。
3. **已发送被 OCR 误判为未知**：客户帧中回复已实际出现，但中文 OCR 将多个字识别成形近字符，旧逻辑要求全文精确相等而返回 `bubble_unresolved`。现仍先要求草稿精确、点击已发生、会话未变化、且证据来自最新连续绿色发出气泡；仅在这些约束全部成立后，对 OCR 文本采用有界编辑距离。真实误识别文本用生产函数回放可通过，不相关的相似长度历史回复仍拒绝。
4. **安全语义保持**：任何未证明点击的失败只允许有界重试；点击后仍无法证明结果时继续保留 `outcome_unknown`，不自动补发。任务护照写入失败也不改变原业务结果。
