# 更新公告发布标准

客户更新后应能在更新公告中查到当前版本修改了哪些内容。公告的唯一内容源为 `src/shared/customer-release-notes.json`，按程序版本记录 `changes` 和可选的 `limitations`，使用客户能理解的表述。每项应写明涉及的功能、之前的问题或触发条件，以及现在的变化；未实机验证的问题如实写明。

每次修复或新增功能准备发布时，先递增程序版本，为新版本填写公告，再构建。构建会校验该版本公告，整包和组件发布脚本自动使用同一份内容；仍可传入说明文件，但其正文须与内置公告一致，否则要求更新源文件并重新构建。隔离的 smoke 更新验证保留单独测试文案。

运行时内置当前版本公告，手动安装或断网也可查看。云端公告仍须验证签名；同版本整包和增量公告合并显示，已读状态按版本保存。本地公告仅用于展示，不参与升级版本选择、安装授权或签名验证。

发布验收：确认客户版本号与公告对应，检查新增和修复条目完整；断网重新打开公告应仍可读，标为已读后重启应保留状态。构建通过、安装包检查、实机微信验证分别记录，不能相互替代。
