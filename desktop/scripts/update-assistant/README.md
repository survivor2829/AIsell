# 官方更新助手

为已有更新入口、却在旧版备份阶段失败的内部测试安装提供一次独立启动入口。自动识别当前用户的测试安装，通过官方 HTTPS 和签名清单获取完整更新，等待软件正常退出后交给现有更新助手；安装、程序回退、资料备份和启动确认复用产品代码。

旧程序在执行下载文件之前就失败，服务器无法让该旧按钮运行尚未下载执行的新逻辑。此入口需要用户运行一次；不会要求逐台采集或选择底座。普通后续升级继续使用应用里的“立即更新”。不宣称完全没有更新能力的历史程序可以凭空获得更新入口。

## 构建

从仓库根目录执行，资源及编译输出均写入 `desktop/.build/update-assistant/`：

```powershell
node desktop/scripts/update-assistant/stage-payload.cjs '<已验收原版运行时能力收据.json>' update
& desktop/scripts/update-assistant/Build-Launcher.ps1 -ResourceDirectory '<上一条输出的directory>'
```

收据必须来自原始制品：任务创建、程序备份和撤销通过，原制品保持不变。准备器重新核对原运行时的逐文件摘要，并收集当前更新代码及锁定依赖，不携带收据中的临时信任配置。暂存资源摘要固化到 EXE；客户不能指定安装路径、跳过签名或切换操作模式。`inspect` 模式只检查、下载和等待，不安装。

现有收据覆盖 1.1.64、1.1.75、1.1.77、1.1.79 的同一 Electron 32.3.3 运行时；按文件身份匹配，应用版本不作为拒绝新版本的条件。以后更换 Electron 时补入核验过的运行时清单，不按每个应用版本维护分支。当前仅测试频道，正式客户频道不开放。

EXE 使用系统 Framework 编译器，无新增运行时下载。内部制品沿用官方分发入口、固定 CA、载荷摘要和 Ed25519 清单校验；当前没有 Windows Authenticode 签名，不宣称已验证发布者。指定发布者指纹构建时，未正确签名的助手会拒绝执行。

## 验证边界

2026-10-12，原生助手在本机实际完成1.1.81→1.1.82的官方签名检查、下载取消、受控断点续传、正式NSIS安装及新版启动ACK，业务资料核对通过。续传验收包含人为准备的缓存断点，不宣称从零完整下载验收。

最终83助手由提交`42ca6f0`重新编译，SHA-256为`eeae563b6f09ad2b945168c948647d7c1bb19a6e00a415dd8da016b6c5d6bb45`。实际核验并下载官方83完整更新后，因用户正在运行82而正确等待；已取消等待并保留下载。83正式安装、启动确认及自动备份退役尚待用户保存操作后完成。

原1.1.64运行时在隔离目录通过HTTPS续传、目标签名、ready/commit、无害安装器和模拟2.0.0启动ACK；最终83载荷再次通过该成功路径。无害安装器失败、新程序启动失败时恢复程序及选择记录、保留业务回执已验证，但不是正式NSIS故障回退或另一台电脑业务验收。详见[发布记录](../../../docs/handoff/2026-10-12-1.1.83-release.md)。

有存活业务或更新进程时等待正常退出，不强杀客户任务。旧失败状态仅在终态证据与签名可验证时退役权限，保留原始回执、下载和备份；无法证明安全的中断安装不会盲目覆盖。取消保留断点下载和恢复依据，未完成的副本不得按目录年龄清理。
